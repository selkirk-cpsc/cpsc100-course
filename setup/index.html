This course uses GitHub Codespaces for all tutorials and assignments. A Codespace is a complete coding setup (editor, terminal, and C compiler) that runs in your web browser. You don't install anything on your computer, and it works the same on Windows, Mac, Chromebook, or a lab computer.

You only have to do Parts 1 to 4 once. After that, the everyday routine is in Part 5.

Never used Git or GitHub before? That's fine, and most of the class hasn't either. You don't need to understand Git to follow these steps. Just follow them in order and check for the ✅ at the end of each part.

What you need:

  • A computer with an up-to-date web browser (Chrome, Edge, Firefox, or Safari)
  • Your Selkirk student email address
  • A phone (for two-factor authentication and for photographing your student ID)
  • About 30 minutes

Part 1: Create a GitHub account

  1. Go to https://github.com/signup.
  2. Enter your Selkirk student email address. Using your school email makes student verification (Part 2) much faster.
  3. Create a password and choose a username.
    • Your instructor will see this username, so keep it sensible. Something like jsmith-dev or jordan-smith works well.
  4. Complete the puzzle and enter the code GitHub emails to you.
  5. If GitHub asks you personalization questions, you can skip them.

Set up two-factor authentication (2FA). GitHub requires this, and you need it for student verification anyway.

  1. Click your profile picture (top right) → Settings → Password and authentication.
  2. Click Enable two-factor authentication.
  3. Follow the steps using an authenticator app on your phone (Google Authenticator, Microsoft Authenticator, or the GitHub Mobile app).
  4. Save your recovery codes somewhere safe, such as a photo or a note on your phone. If you lose your phone and don't have these codes, you can be locked out of your account.

✅ Done when: you can log in to github.com and 2FA is turned on.

Part 2: Get verified as a student (free extra Codespace hours)

Every GitHub account gets some free Codespace time each month. Verified students get GitHub Pro for free, which gives you 50% more Codespace time. That's enough for this course.

Free account Verified student (GitHub Pro)
Codespace time per month* about 60 hours about 90 hours
Storage 15 GB 20 GB

*On the standard 2-core Codespace, which is what this course uses. The allowance resets each month.

How to apply:

  1. Go to https://education.github.com/pack and click Start an application (or Sign up for Student Developer Pack).
  2. Choose Student.
  3. Select your Selkirk student email (add it to your GitHub account first if it isn't there already) and choose Selkirk College as your school.
  4. When asked for proof, take a photo of your student ID card with your phone or webcam. A photo of your class schedule or enrolment letter with the current date also works.
  5. Submit.

Tips so you don't get rejected:

  • Apply while you're on campus Wi-Fi if you can. GitHub checks your location, and applying from campus helps.
  • GitHub may ask you to fill in your billing information (just your legal name and address, not a credit card). Your name there must match the name on your ID.
  • Make sure your GitHub profile has your real name filled in.

Approval usually takes a few days. You'll get an email when it goes through. You don't need to wait for approval to continue. Go ahead with Part 3 now.

You won't be charged. Unless you add a credit card and raise your spending limit (don't), GitHub can't bill you. If you use up your monthly hours, Codespaces pauses until next month. That's why the student upgrade and the habits in Part 5 matter.

✅ Done when: you've submitted the application. Approval can arrive later.

Part 3: Make your own copy of the CPSC 100 course repository

A repository (or "repo") is a project folder stored on GitHub. I've made a template repo with everything you need for this course. You'll make your own copy of it, and all your work for the term lives there.

  1. Make sure you're logged in to GitHub, then open the course template: ➡ https://github.com/rbrad070/cpsc100-template
  2. Click the green Use this template button (top right) → Create a new repository.
  3. Fill in the form:
    • Owner: your username (should already be selected)
    • Repository name: cpsc100-work
    • Visibility: choose Private. ⚠️ This matters, because a public repo lets anyone see (and copy) your work.
  4. Click Create repository.

You'll land on the page for your new repo. The address bar should show github.com/YOUR-USERNAME/cpsc100-work.

⚠️ Use "Use this template", not "Fork" and not "Download ZIP". Those won't give you a repo you can save your work to properly.

✅ Done when: you have a private repo called cpsc100-work under your username.

Part 4: Open your repo in a Codespace

  1. On your repo page (github.com/YOUR-USERNAME/cpsc100-work), click the green <> Code button.
  2. Click the Codespaces tab.
  3. Click Create codespace on main.
  4. Wait. The first launch takes 2 to 5 minutes while it sets up the C compiler and tools. Later launches are much faster.

When it's ready, you'll see an editor in your browser that looks like this:

┌────────────────┬─────────────────────────────────────┐
│  EXPLORER      │                                     │
│  (your files)  │        EDITOR                       │
│                │        (the file you're working on) │
│  > assignments │                                     │
│  > tutorials   │                                     │
│    README.md   │                                     │
│                ├─────────────────────────────────────┤
│                │  TERMINAL                           │
│                │  @you ➜ /workspaces/cpsc100-work $  │
└────────────────┴─────────────────────────────────────┘

Check that everything works. Click in the terminal at the bottom, type this, and press Enter:

gcc --version

If you see a version number (something like gcc (Ubuntu 13.x...)), you're all set.

If the terminal isn't showing, open it with the menu ☰ (top left) → Terminal → New Terminal.

About the .devcontainer folder: do not change or delete it

Your repo contains a folder called .devcontainer with a file called devcontainer.json. This file sets up your Codespace: it installs the C compiler and tools, and it turns off autocomplete and AI coding assistants (like GitHub Copilot).

Those features are off on purpose. This course is about learning to write code yourself, and you'll be writing code by hand on tests. Do not edit, move, or delete this folder or file, and do not install Copilot or other AI extensions. Changing this setup counts as a violation of the course's academic integrity policy.

As a verified student, GitHub may offer you free Copilot. That's fine for other projects, but don't use it for CPSC 100 work.

Read the README and do your first task

Your repo has a file called README.md with a short guide to using the terminal and compiling your programs. It ends with your first task: compiling and running a welcome program in the tutorials folder and another in the assignments folder.

  1. In the Explorer on the left, right-click README.md → Open Preview to read it with formatting. (You can also read it on your repo's page on github.com.)
  2. Read it all the way through, then follow the steps under Your first task: run the welcome programs.

✅ Done when: your Codespace is open, and both welcome programs print their messages.

Part 5: Everyday use

Coming back to your Codespace later

Don't create a new Codespace every time. Reopen the one you already have:

  • Go to https://github.com/codespaces (bookmark it!), find your cpsc100-work Codespace, and click it.
  • Or: your repo page → <> Code → Codespaces tab → click your existing Codespace.

Your files will be exactly as you left them.

Writing C code

Your repo has two main folders: tutorials and assignments. Keep each tutorial or assignment in its own folder inside one of these, for example tutorials/tut03 or assignments/a1.

  • Create a folder: right-click tutorials or assignments in the Explorer → New Folder... → name it, e.g. tut03.
  • Create a file: right-click the folder → New File... → name it, e.g. hello.c.
  • Open a file: click it in the Explorer on the left.
  • Save: Ctrl + S (Windows/Chromebook) or Cmd + S (Mac). A ● dot on the file's tab means it has unsaved changes.

Don't use spaces in folder or file names. Use tut-03 or tut_03, not tut 03. Spaces make terminal commands much harder to type.

Compiling and running your program

You compile in the terminal with gcc. The terminal must be in the same folder as your .c file, or gcc won't find it.

Step 1: Open a terminal in the right folder. In the Explorer, right-click the folder that holds your .c file (e.g. tut03) → Open in Integrated Terminal. A new terminal opens that's already in that folder.

Step 2: Check you're in the right place. The terminal prompt shows which folder you're in:

@jsmith ➜ /workspaces/cpsc100-work/tutorials/tut03 (main) $

Type ls and press Enter. Your .c file should be in the list. If it isn't, you're in the wrong folder, so go back to Step 1.

Step 3: Compile.

gcc -Wall -Wextra -std=c11 -g hello.c -o hello
Part What it means
gcc Run the C compiler
-Wall -Wextra Show warnings about likely mistakes. Read them and fix them!
-std=c11 Use the C11 version of the C language
-g Include information for the debugger
hello.c Your source file (the code you wrote)
-o hello Name the finished program hello

If nothing is printed, it compiled with no errors or warnings. If you see errors, fix your code, save, and compile again.

Step 4: Run.

./hello

The ./ means "the program in this folder".

Tip: you don't have to retype the long gcc command. Press the up arrow (↑) to bring back earlier commands, then press Enter.

Moving between folders in the terminal. If your terminal is in a different folder, use cd to move. From the top of your repo (/workspaces/cpsc100-work):

cd tutorials/tut03             # go into tutorials, then tut03
cd ..                          # go back up one folder
cd /workspaces/cpsc100-work    # jump back to the top of your repo

Press Tab while typing a folder name and the terminal fills in the rest for you.

Handy terminal commands:

Command What it does
ls List the files in the current folder
cd foldername Go into a folder
cd .. Go back up one folder
pwd Show which folder you're in
clear Clear the terminal screen
↑ (up arrow) Bring back your previous command
Ctrl + C Stop a program that's stuck or running forever

Saving your work to GitHub (committing)

Saving a file (Ctrl + S) is not the same as saving it to GitHub. Your files live inside the Codespace. To back them up to your GitHub repo, you commit and sync.

⚠️ Why this matters: GitHub automatically deletes Codespaces that haven't been used for 30 days, and a Codespace can occasionally break. Anything you haven't committed and synced is lost. Anything you have committed is safe in your repo forever.

Commit at the end of every work session, and any time you finish something you'd hate to lose.

  1. Click the Source Control icon in the left sidebar (it looks like a branching line, and it shows a number badge when you have changes). Shortcut: Ctrl + Shift + G.
  2. You'll see a list of the files you changed.
  3. In the Message box at the top, type a short description of what you did, e.g. Finished tutorial 2 part 1.
  4. Click ✓ Commit.
    • If a pop-up asks "There are no staged changes to commit. Would you like to stage all your changes?", click Always. (Staging just means "include these files in the commit.")
  5. Click Sync Changes (the button that appears in the same spot). This sends your commit up to GitHub.
    • If it asks about pushing and pulling, click OK or OK, Don't Show Again.

Check that it worked: go to your repo page on github.com and refresh. You should see your commit message next to the files you changed.

Prefer the terminal? (optional) 
git add .
git commit -m "Finished tutorial 2 part 1"
git push

When you're done for the day

  1. Commit and sync (above).
  2. Stop the Codespace so it doesn't use your monthly hours: click Codespaces in the blue bar at the bottom-left of the screen → Stop Current Codespace. You can also stop it from https://github.com/codespaces (click ••• → Stop codespace).

Codespaces stop on their own after 30 minutes of inactivity, but stopping manually saves hours. Closing the browser tab does not stop it right away.

To see how many hours you've used this month, go to https://github.com/settings/billing.

Part 6: Downloading your work to submit

Assignments and tutorials are submitted on Moodle as files. Here are two ways to get your files out of the Codespace and onto your computer.

Option A: Download straight from the Codespace (easiest)

  1. In the Explorer on the left, right-click the file (e.g. a1.c) or the whole folder (e.g. a1).
  2. Click Download....
  3. Your browser saves it to your computer, usually in your Downloads folder. A folder downloads as a .zip file.
  4. Upload that file to the assignment on Moodle.

If your browser asks for permission to download or to access a folder, click Allow.

Option B: Download from your GitHub repo page

This downloads the version you last committed and synced, so do that first.

  • One file: on your repo page, click through the folders to the file, then click the Download raw file button (⤓ icon, top right of the file view).
  • Everything: on your repo page, click <> Code → Download ZIP.

Before you submit, always open the downloaded file to make sure it's the right one and contains your latest work.

Quick reference: every work session

1. Open    → github.com/codespaces → click your cpsc100-work Codespace
2. Work    → edit, Ctrl+S to save
3. Compile → right-click your folder → Open in Integrated Terminal
             gcc -Wall -Wextra -std=c11 -g hello.c -o hello   then   ./hello
4. Commit  → Source Control → type a message → ✓ Commit → Sync Changes
5. Stop    → Codespaces (bottom-left) → Stop Current Codespace
6. Submit  → right-click file/folder → Download... → upload to Moodle

Troubleshooting

Problem What to do
gcc: error: hello.c: No such file or directory The terminal is in the wrong folder, or the file name is spelled differently. Type ls to see what's in the current folder, then see "Compiling and running your program" in Part 5.
bash: ./hello: No such file or directory The program wasn't built. Scroll up for gcc errors, fix them, and compile again.
The Codespace is stuck loading Refresh the browser tab. If it's still stuck after a few minutes, go to github.com/codespaces, click ••• next to it → Stop codespace, then open it again.
I don't see the "Use this template" button Make sure you're logged in to GitHub and on the course template page, not your own repo.
I see "Fork" instead of my own repo You forked by mistake. Delete the fork (repo Settings → scroll to the bottom → Delete this repository) and redo Part 3.
"You've used your included Codespaces hours" Your monthly hours are used up. Make sure you applied for student verification (Part 2) and are stopping your Codespace when done. Download your files (Part 6) and talk to your instructor.
Sync Changes gives an error Take a screenshot and bring it to your instructor or post it in the course forum. Don't delete the Codespace, because your uncommitted work is still inside it.
Student verification was rejected Read the reason in the email. Usually the name didn't match your ID, or the photo was unclear. Fix it and reapply (from campus Wi-Fi if possible).
I accidentally deleted a file If you had committed it before: go to your repo on github.com, find the file, and copy it back. If you hadn't, ask your instructor.

Still stuck? Ask in class, come to office hours, or post in the Moodle forum with a screenshot of what you're seeing.

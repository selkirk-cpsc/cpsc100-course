What’s Actually Inside char name[50]?

char name[50] reserves 50 bytes of contiguous memory, one char per box.

A string is not a separate C data type, it is a convention for using a char array:

  • The characters of the text are stored one per element, in order

  • A special sentinel value, the null terminator '\0', is stored in the element right after the last real character

  • Everything after that in the array is unused, leftover memory. C does not care what garbage is sitting there

This is the entire definition of a “string” in C. There is no length field, no special type, just an array and a rule about where it ends.

The Null Terminator

'\0' has many names – null character, binary zero, ASCII 0, string terminator.

C adds it automatically for a string literal:

char month[10] = "January";

7 letters, then '\0' in element 7. Elements 8 and 9 are unused; a string literal sets them to '\0' too.

Every statement that reads a string, printf("%s", ...), strlen(), all of them, works by reading characters until it hits '\0'.

Building a String One Character at a Time

Since a string is just an array, you can fill it by hand, element by element:

char month[10];
month[0] = 'M';
month[1] = 'a';
month[2] = 'y';
month[3] = '\0';   // you must add this yourself!

Forget the '\0' and printf("\%s", month) keeps reading past the end of the array →\rightarrow printing whatever garbage bytes happen to follow in memory, until it randomly finds a zero byte somewhere.

Forgetting '\0'

#include <stdio.h>

int main(){
  char month[10];
  month[0] = 'M';
  month[1] = 'a';
  month[2] = 'y';
  //month[3] = '\0';
  printf("%s\n", month);
  return 0;
}

Output after compiling then running the program a few times:

1st execution output: May#@!
2nd execution output: May}Sr$
3rd execution output: MaynTR%
4th execution output: May

Notice that the 4th execution printed the correct string "May"! That run worked only because month[3] happened to hold a 0 byte. Failing to add '\0' doesn’t always produce garbage output, but reading past the end of the characters you set is undefined behavior: you no longer have control over what the output will be.

C Will Not Protect You

This is the central fact about strings in C:

  • There is no bounds checking

  • Reading or writing past the null terminator, or past the end of the array itself, is undefined behavior: it may crash, print garbage, or silently corrupt other variables

  • You are responsible for making sure the array is big enough and the terminator is where it should be

Keep this in mind for the rest of the lecture →\rightarrow every string operation we cover is really a loop that trusts this convention.

Strings and Loops

A String Is Just an Array

We just saw that a string is a char array with elements you can index. Walking it is a loop like the ones from previous weeks:

  • Instead of looping a fixed number of times, we loop until we see the terminator

  • This one pattern, start at index 0 and keep going while word[i] != '\0', underlies almost every string operation you will ever write

<string.h>

<string.h> Is Not Magic

Every function in <string.h> is a loop like the ones you just wrote, following the same null-terminator convention.

strlen(word) walks the array just like the letter counter: start at index 0, stop at '\0', return how far you got.

The library version is more carefully optimized, but the idea is identical.

Tutorial 6: you will build the flow diagrams for the loops hidden inside strlen, strcpy, and strcat yourself.

The Rest of the Library

Once you accept that strlen is “just a loop,” the rest of <string.h> is easier to trust:

  • strcpy(dest, src) – copies characters until it copies a '\0'

  • strcmp(a, b) – walks both strings together comparing characters

  • strcat(dest, src) – finds dest’s terminator, then copies src on from there

  • Safer bounded versions exist too: strncpy, strncat – they take a maximum length so they can’t run past the end of your array

We are not learning these today. You will use each of them hands-on, and predict their output first, in Tutorial 6’s guided segment. For now, the point is: they all trust the same terminator convention strlen does.

Reading Strings Safely

scanf("%s", ...) Stops at Whitespace

You met this in Week 2:

char name[10];
printf("Enter your name: ");
scanf("%s", name);

  • %s reads a single word – it stops at the first space, tab, or newline

  • Type "Ryan Bradshaw" and name only gets "Ryan"

  • Worse: nothing stops scanf("%s", name) from writing past the end of a 10-byte array if you type more than 9 characters

fgets(): Reading a Whole Line

fgets() reads an entire line, spaces included, and takes a size limit:

char name[50];
printf("Enter your name: ");
fgets(name, sizeof(name), stdin);

  • sizeof(name) tells fgets() the array’s real size – it will never write more characters than that

  • stdin is the standard input stream – by default, whatever you type at the keyboard; it tells fgets() where to read from, the same way scanf() always reads from the keyboard implicitly

  • It reads up to and including the newline character, and keeps the '\n' in the string (something to watch for)

  • This is why fgets() is the safer default for reading text from a user

Buffer Overflows

A buffer overflow happens when you write more characters into an array than it can hold:

char small[5];
strcpy(small, "this string is way too long");  
// overflow!

  • strcpy keeps copying past the end of small – it has no idea how big small is

  • The extra bytes land on whatever memory comes next – other variables, or worse

  • This is one of the most common bugs in C, and historically one of the most common security vulnerabilities in real software

Always give your array a size limit that any read or copy respects – a field width on scanf ("\%49s" for a 50-char array – see lecture 3) , sizeof with fgets, or strncpy/strncat instead of their unbounded cousins.

Why Arrays?

The Problem: Many Related Values

Suppose you need to store the midterm marks for 30 students.

  • One variable per student? mark1, mark2, …\ldots , mark30;

  • That’s unworkable: no way to loop over them, no way to index by student number, and it doesn’t scale.

An array lets you store a collection of values of the same type under a single name. A string, which you just met, was already a special case of this: an array of char .

Declaring an Array

int marks[30];      // 30 integers
float averages[10]; // 10 floats
char name[20];       // 20 characters

  • The number in [ ] at declaration time is the size →\rightarrow how many elements to reserve space for.

  • All elements share the same type and are the same size in memory.

  • The elements are stored contiguously; back-to-back, in one unbroken block of memory — exactly like the char array you just saw for strings.

Indexing

Indexing: Accessing Elements

int marks[30];

marks[0] = 85;   // first element
marks[1] = 92;   // second element
marks[29] = 77;  // last element

  • An index is an offset from the start of the array →\rightarrow marks[i] means “the element i positions after the first one.”

  • That’s exactly why indexing starts at 0: marks[0] is 0 positions from the start →\rightarrow it is the start.

  • For an array of size N, valid indices run from 0 to N-1.

No Bounds Checking

C does not check that your index is in range. You already know this rule for strings; it applies to every array.

int marks[30];
marks[30] = 100;  // compiles. runs. corrupts something.

  • marks[30] is one past the last valid index (0–29); this is undefined behavior.

  • It might crash. It might silently overwrite an unrelated variable. It might appear to work today and fail next week.

  • There is no safety net; you are responsible for staying in bounds.

Initializing Arrays

int scores[5] = {90, 85, 77, 60, 100};

  • Listing more values than the declared size is a compile error.

  • Listing fewer values leaves the remaining elements set to 0:

int scores[5] = {90, 85};  // {90, 85, 0, 0, 0}
int scores[] = {90, 85, 77, 60, 100};
// size 5, inferred

Iterating Arrays with a Loop

The Standard Pattern

Arrays and for loops belong together: the loop variable is the index. This is the same pattern you just used to walk strings, minus the null-terminator check.

int scores[5] = {90, 85, 77, 60, 100};

for (int i = 0; i < 5; i++) {
    printf("%d, ", scores[i]);
}
Sample run
90, 85, 77, 60, 100,

  • Start at i = 0, stop before i reaches the size (i < 5, not i <= 5); this is what keeps you in bounds.

  • This pattern; read, sum, search, compare; is how almost every array problem gets solved.

Why Not strlen()?

With strings we looped until strlen(); why hard-code 5 here?

  • strlen() counts characters until it finds '\0'; only strings carry that end marker.

  • An int array has no terminator: 0 is a perfectly valid score, so nothing marks where the data stops.

  • An array does not remember its own length, so you must track it.

Rather than repeating 5 everywhere, name it once (#define from lecture 3):

#define NUM_SCORES 5
int scores[NUM_SCORES] = {90, 85, 77, 60, 100};
for (int i = 0; i < NUM_SCORES; i++) { ... }

Example: Sum and Average

int scores[5] = {90, 85, 77, 60, 100};
int sum = 0;

for (int i = 0; i < 5; i++) {
    sum += scores[i];
}

float average = sum / 5.0;
printf("Average: %.2f\n", average);
Sample run
Average: 82.40

  • Accumulate into a variable declared before the loop, initialized to 0; the same accumulator pattern from earlier weeks, now driven by an index instead of input.

Two-Dimensional Arrays

Declaring a 2D Array

An array can hold rows of arrays, forming a grid:

int grid[2][3];
// 2 rows, 3 columns --> 6 elements

Access an element with two indices, row then column:

grid[0][0] = 1;
grid[0][1] = 2;
grid[1][2] = 9;

Row-Major Order

It looks like a grid, but C actually stores it as one contiguous strip of memory, traversed in the order the arrow follows:

grid[0][0], grid[0][1], grid[0][2], grid[1][0], grid[1][1], grid[1][2]

Row 0 is laid out completely, then row 1 immediately after it →\rightarrow this is row-major order.

Finding an Element in the Strip: Offset

Because the grid is really one strip, every element has an offset: how many elements it sits from the start of the strip (just like a 1D index).

To reach grid[row][col]: skip row full rows, then move col more: offset=𝚛𝚘𝚠×(elements per row)+𝚌𝚘𝚕\text{offset} = \texttt{row} \times (\text{elements per row}) + \texttt{col}

grid[1][2]: skip 1 row of 3, then 2 more →\rightarrow 1×3+2=𝟓1 \times 3 + 2 = \mathbf{5}. C does this arithmetic for you every time you write grid[row][col].

Iterating a 2D Array

Same nested-loop pattern from Week 5; outer loop over rows, inner loop over columns:

int grid[2][3] = {{1, 2, 3}, {4, 5, 6}};

for (int row = 0; row < 2; row++) {
    for (int col = 0; col < 3; col++) {
        printf("%d ", grid[row][col]);
    }
    printf("\n");
}
Sample run
1 2 3 
4 5 6

  • Outer loop index selects the row; inner loop index sweeps across the columns of that row.

  • This is sufficient for most intro-level use; dynamically-sized 2D grids are a later-course topic.

Summary

Summary

  • A string is a char array ending in '\0' – nothing more

  • Every loop pattern from Week 5 applies: walk the array until you hit the terminator (strings) or the size (arrays)

  • <string.h> functions – strlen, strcpy, strcmp, strcat, and their safer strn versions – are loops like yours, following the same rule (full tour in Tutorial 6)

  • scanf("\%s", ...) reads one word; fgets() reads a whole line and respects a size limit

  • C never checks array bounds for you – writing past the end is a buffer overflow for strings, or plain undefined behavior for any other array; it’s on you to prevent it

  • Arrays: a collection of same-typed values in one contiguous block, indexed from 0; for loops are the standard way to walk them, one dimension or two

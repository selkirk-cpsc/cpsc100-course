Functions

Breaking a Big Task Into Small Ones

Every program you’ve written so far has been one long sequence of statements in main().

As a program grows, that stops working:

  • main() becomes hundreds of lines long

  • the same logic gets copy-pasted every time you need it again

  • it’s hard to find and fix a bug buried in the middle of it all

Decomposition is the fix: break a large task into smaller, named subtasks. This is the core habit of software design — and it’s exactly what a function lets you do.

What Is a Function?

In C, a function is a self-contained block of code that performs a specific task. It can take input values, execute a series of statements, and optionally return a result to the caller.

Why Use a Function?

Functions are useful for:

  • Avoiding repetition →\rightarrow replacing commonly used sections of code

  • Improving organization:

    • Separating code into smaller, single-purpose parts

    • Making programs more modular and readable

    • Simplifying debugging and maintenance

Functions as a Contract

Think of a function as a contract:

  • Given these inputs (its parameters)…

  • …it produces this output (its return value).

The caller doesn’t need to know how the function does its work. Only what it needs to give it, and what it will get back.

The Anatomy of a Function

Every function has the same five parts:

return_type function_name( parameter list ) {
    // body
    return value;
}

  • return type →\rightarrow the kind of value it gives back

  • name →\rightarrow how you call it

  • parameter list →\rightarrow what inputs it expects, and their types

  • body →\rightarrow the statements that do the work

  • return →\rightarrow sends a value back to the caller

Declaration and Definition

A function in C is made up of two parts:

  • Declaration (prototype): tells the compiler the function’s name, return type, and parameters before it is used

  • Definition: contains the actual block of code that runs when the function is called

You can think of the declaration as a promise, and the definition as the delivery of that promise.

Example

int is_factor(int x, int y)
{
    int result = x % y;
    return (result == 0);
}

The function’s prototype is:

int is_factor(int x, int y);
// returns an integer
// and takes two integer arguments x and y

and its definition is the statements in the body:

int result = x % y;
return (result == 0);

The void Type in Function Declarations

void is a special type meaning "no type" or "nothing". It is used in two ways:

  • As a return type →\rightarrow the function does not return a value

  • As a parameter list →\rightarrow the function takes no arguments

void greet(void);     // no return value, 
                      // no parameters

Writing (void) explicitly (rather than leaving the parameter list empty) is preferred in modern C, to make the intent clear.

Arguments vs. Parameters

These two words get used interchangeably in casual conversation, but they mean different things:

  • An argument is a value passed into a function at the call site.

  • A parameter is the name the function’s definition uses to refer to that value.

Put another way: parameters are part of the function’s definition; arguments are given when the function is called.

void average(int a, int b);   // a, b are parameters

average(x, y);                // x, y are arguments

Function Prototypes

Where Function Declarations Go

In C, every function must be declared before it is used, this lets the compiler check the return type and the number and types of its parameters at the call site.

Two common ways to organize your functions:

  1. Place the function definition before main() →\rightarrow the compiler sees the function before it’s called

  2. Place only a prototype before main(), and the full definition later in the file →\rightarrow this improves readability

Example: Both Are Equivalent

Declaration and definition separated:

#include <stdio.h>

/* prototype */
void greet(void);

int main(void) {
    greet();
    return 0;
}

void greet(void) {
    printf("Hello!\n");
}

Declared and defined together:

#include <stdio.h>

void greet(void) {
    printf("Hello!\n");
}

int main(void) {
    greet();
    return 0;
}

greet() has no return statement: a void function returns to its caller when it reaches its closing brace.

The Pitfall: Using a Function Before It’s Declared

If the compiler hasn’t seen a prototype or a definition for a function by the time it’s called, you get a "used before declared" style error.

int average_of_two(int a, int b)
{
    return total(a, b) / 2;  // total() used before declared
}

int total(int a, int b)    // total() has no prototype above main()
{
    return a + b;
}

average_of_two() calls total() on line 3, but the compiler hasn’t seen anything about total yet; not a prototype, not a definition.

The Fix: Add a Prototype

#include <stdio.h>

int average_of_two(int a, int b);
int total(int a, int b);   // FIX: prototype before main()

int main(void)
{
    printf("%d\n", average_of_two(4, 6));
}

int average_of_two(int a, int b)
{
    return total(a, b) / 2;  // total() is now declared
}

int total(int a, int b)
{
    return a + b;
}

main()

A Familiar Example: main()

A function prototype you already know:

int main(void)

  • main() is the entry point of every C program →\rightarrow when your program starts, the operating system automatically calls it

  • Every C program must contain exactly one main() function →\rightarrow it defines where execution begins and ends

  • return 0; (or EXIT_SUCCESS) signals to the OS that the program finished successfully

Flow Diagrams

A New Shape: The Function Call

Recall our flow-diagram shapes: oval (Start/Stop), rectangle (process), parallelogram (I/O), diamond (decision), and a dashed box around a loop body.

This week we add one new shape: a rectangle with a vertical bar at each end.

  • It is a single labeled block in a top-level diagram

  • Its internals live in a separate diagram

  • That block is a function call.

  • Its diagram’s ovals: function_name(parameters) instead of Start, return value instead of Stop (just return for a void function)

The side bars say “this step is defined somewhere else.” The dashed box still means only loop body.

The Prime Checker

Top-Level Diagram: Checking If a Number Is Prime

Read a number from the user and report whether it’s prime. At the top level, we don’t care how the check works; only that is_prime(n) is a single labeled step.

Internals: What’s Inside is_prime(n)

This diagram expands the function-call box from the previous slide: what happens once is_prime(n) is called.

  • Start with prime = 1

  • n < 2: set prime = 0

  • Otherwise test divisors up to n\sqrt{n}; on a hit, set prime = 0 and break

  • Return prime once, at the end

The Code: main()

#include <stdio.h>

// Prototype: declare before use
int is_prime(int n);

int main(void) {
    int n;
    printf("Enter a number: ");
    scanf("%d", &n);

    // is_prime() returns 1 (true) or 0 (false)
    if (is_prime(n))
        printf("%d is prime\n", n);
    else
        printf("%d is not prime\n", n);

    return 0;
}

The Code: is_prime()

// Returns 1 if n is prime, 0 otherwise
int is_prime(int n) {
    int prime = 1;              // assume prime

    if (n < 2) {                // below 2: not prime
        prime = 0;
    } else {
        // Only test divisors up to sqrt(n): i * i <= n
        for (int i = 2; i * i <= n; i++) {
            if (n % i == 0) {   // i divides n evenly
                prime = 0;
                break;          // stop looking
            }
        }
    }
    return prime;               // one return, at the end
}

Pass-by-Value

Passing Variables Into a Function

When a variable is passed to a function in C, the function receives its own local copy of the value.

  • The original variable in the caller is not changed

  • This is called pass-by-value

  • C always copies the argument into the parameter →\rightarrow only the called function can use its copy, and only while it runs

A consequence: a function cannot change the caller’s variable this way. (There’s a way around this, pointers, but, that’s a topic for another day.)

Example: Computing an Average (Pass-by-Value)

#include <stdio.h>

void average(int a, int b);

int main(void) {
    int x = 8, y = 6;

    average(x, y);

    return 0;
}

void average(int a, int b) {
    float avg = (a + b) / 2.0;
    printf("Average of %d and %d = %.1f\n",
           a, b, avg);
}

Output:

Average of 8 and 6 = 7.0

Explanation:

  • x and y are passed by value to average() (line 8).

  • average() receives its own copies of x and y, called a and b, and prints a result.

Example: Swapping Variables (Pass-by-Value)

#include <stdio.h>

void swap(int a, int b);

int main(void) {
    int x = 3, y = 7;

    printf("Before: x=%d, y=%d\n", x, y);
    swap(x, y);
    printf("After:  x=%d, y=%d\n", x, y);

    return 0;
}

void swap(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
    printf("Inside swap: a=%d, b=%d\n", a, b);
}

Output:

Before: x=3, y=7
Inside swap: a=7, b=3
After:  x=3, y=7

Explanation:

  • swap() receives copies of x and y.

  • The swap works inside the function, but only on the local copies a and b.

  • When the function ends, those copies are destroyed. The originals in main() stay unchanged.

When to Extract a Function

When Should You Pull Code Out Into a Function?

A few signals that a block of code wants to become its own function:

  • You’ve written the same logic more than once →\rightarrow extract it once, call it from everywhere

  • A block of code does one clearly nameable thing →\rightarrow if you can describe it in a short verb phrase (is_prime, average, square_elements), it’s probably a function

  • A section of main() is getting long enough that you have to scroll to see the whole thing

  • You want to test a piece of logic on its own, without running the entire program

Memory

Memory

Before introducing pointers, we first review our mental picture of memory

– a long sequence of numbered storage locations.

Understanding Memory (Before Pointers)

Every program you write uses the computer’s memory (RAM) to store data.

  • Each piece of data; a variable, array element, or character; lives in a specific location in memory.

  • These locations are numbered so the computer can keep track of where things are stored.


A RAM stick (memory module)

Photo: PantheraLeo1359531, CC BY 4.0, via Wikimedia Commons

Variables and Memory

When you declare a variable, you’re asking the computer to:

  1. Reserve space in memory.

  2. Associate that space with a name.

Example:

int x = 42;

The variable x is stored somewhere in memory, and the computer remembers both:

  • its value (42)

  • its location (address in memory)

What is a Memory Address?

A memory address is a numeric label that tells the computer where a value is stored.

  • Every byte in memory has its own unique address.

  • You can think of memory like a long row of numbered boxes:

Number Bases Refresher

  • Binary (base 2): digits 0,1; natural for hardware.

    • Example: 1010 = 10 in decimal

  • Decimal (base 10): digits 0,1,…\ldots9; natural for humans.

  • Hexadecimal (base 16): digits 0,1,…\ldots9,A,B,…\ldotsF; a compact, human-friendly view of binary.

    • Example: 0x2A = 42 in decimal = 0010 1010 in binary

    • The prefix 0x means "this number is written in hexadecimal."

Key Idea

Computers think in binary, humans think in decimal, and programmers often use hexadecimal to bridge the two.

Memory Address Numbers

A memory address is simply a number used to label a specific byte in RAM.

The same address can be written in different number systems:

Base Representation Comment
Binary 1111 1010 0110 1101 1010 0011 0111 1001 Very long
Decimal 4,208,935,033 Compact but hard to relate to bits
Hexadecimal 0xFA6DA379 Short and byte-aligned

Key Idea

All three forms represent the same address; hexadecimal is just the most convenient way to view it.

Why Are Memory Addresses in Hexadecimal?

Addresses are really just numbers; but very large ones!

  • Writing binary would be too long and hard to read.

  • Decimal values don’t map neatly to the binary byte format used by computers.

  • Hexadecimal (base 16) is a compact, readable way to represent binary data.

  • Each hex digit corresponds exactly to 4 bits: 𝟶𝟶𝟶𝟶=0,𝟷𝟷𝟷𝟷=F\texttt{0000} = 0, \quad \texttt{1111} = F

Example

0x7FFD4D0B82A0 means "the address stored in memory," and the 0x just tells us it’s written in hexadecimal.

Bringing It Together

  • Every variable has:

    • a name (what you write in code)

    • a value (the data stored)

    • a memory address (where it lives)

  • Hexadecimal is just how we display those addresses.

Pointers

Solving the Mystery of Pointers

Pointer variables, often called pointers, let you do much more with C than a language without pointers.
They are often a point of challenge for students. But don’t worry, I will point you in the right direction.
After learning pointers people often ask “What is the point”. I usually answer, “What would be the point of all these jokes without pointers!”
My friends make a point of not talking to me.

What are Pointers?

Things to consider:

  • C stores your program’s data in memory.

  • Each location in memory has a unique address.

  • Every variable you create is stored somewhere in memory.
    Example: 0x7FFCC8D6CF10 (Memory address in hexadecimal)

  • It’s easier for humans to remember a name (e.g., orderNum) than a numeric address.

Definition

A pointer is a variable that stores a memory address.

  • Instead of holding a value like 42, it holds the address of another variable.

  • You can think of a pointer as a "map location" →\rightarrow it tells the program where in memory to find something.

Defining a Pointer

Here two variables are defined

int num;
float value;

Next two corresponding pointers are defined,

int *pNum;
float *pValue;

  • the * before the variable name means it is a pointer

  • often pointers are named with a ‘p’ at the beginning
    (pNum will point to num)

New Operators

New operators are introduced,

Operators Description
& Address-of operator
* Dereferencing operator

  • address-of: looks up the address of a variable

  • dereferencing: define or access the value of a pointer

Using the Address-of Operator &

Example:

int age = 19;
int *pAge = &age;

What happened here?

  • created the variable age and made space in the memory

  • initialized the value of age equal to 19

    • looked up the address using the variable name age

  • created a pointer pAge and initialized it to point to the address of age (say 0x7FFD for example)

Using the Dereferencing Operator *

Once you link an address to a pointer you can access the variable using the pointer.

Example,

int age; // Declares empty int called age
int *pAge = NULL; // Creates a pointer; points nowhere yet

pAge = &age; // Links the pointer to age
age = 19; // Sets the value of age
printf("Values of age, pAge: %d %d\n", age, *pAge);
// Output: Values of age, pAge: 19 19

*pAge = 25; // Sets the value of age
printf("Values of age, pAge: %d %d\n", age, *pAge);
// Output: Values of age, pAge: 25 25

Notice:

  • Initially * operates by creating the pointer pAge at declaration
    (line 2)

  • After declaration, * operation on pAge changes; it accesses the value that pAge is pointing to and changes it to 25 (line 9).

Pointers Must Match Variable Types

Every pointer in C is declared to point to a specific data type.

  • A pointer to an int can only store the address of an int variable.

  • A pointer to a float can only store the address of a float, and so on.

  • This type matching ensures that the compiler knows how many bytes to read or write when the pointer is used to access memory.

int age = 19;
float price = 5.99;

int *pAge = &age;       //  correct: int* points to int
float *pPrice = &price; //  correct: float* points to float

pAge = &price;           // error: incompatible types

Key Idea: The pointer type must match the variable type it points to; this keeps memory access safe and predictable.

NULL: A Pointer That Points to Nothing

int *pNum = NULL;   // pNum doesn't point anywhere 
                    // yet

if (pNum != NULL) {
    printf("%d\n", *pNum);  // safe: only dereference
} else {                    // if it isn't NULL
    printf("pNum has nothing to point to.\n");
}

  • NULL is a special address value meaning “points to nothing valid.”

  • Dereferencing a NULL pointer crashes your program (segmentation fault); always check before you dereference.

  • An uninitialized pointer is worse than NULL: it holds garbage, and dereferencing it can silently corrupt memory instead of crashing cleanly. Always initialize a pointer, even if only to NULL.

Example: Dereferencing Without Checking

int *pNum = NULL;

printf("%d\n", *pNum);   // no NULL check!
printf("This line never runs.\n");

Running it:

$ ./a.out
Segmentation fault (core dumped)

  • *pNum tries to read through an address that doesn’t point anywhere valid; the operating system kills the program on the spot.

  • Nothing after the crash runs; not the second printf, not any cleanup code later in main().

  • The fix is exactly the if (pNum != NULL) check from “NULL: A Pointer That Points to Nothing”; always check before you dereference, not after something goes wrong.

Example: An Uninitialized Pointer

int *pNum;   // never given a value

if (pNum != NULL) {
    printf("%d\n", *pNum);
} else {
    printf("pNum has nothing to point to.\n");
}

Running it twice:

$ ./a.out
-1221434385
$ ./a.out
-1611562001

  • The check can’t help: garbage usually isn’t NULL, so the program follows an address nobody chose.

  • No crash and no message, just a wrong number. Other runs or compiler settings could crash or take the else instead.

  • Start at NULL and the check works every time.

Why Pointers Matter

Pointers may seem abstract now; they’re just memory addresses! But they give us a way to directly access and control memory.

  • C uses addresses everywhere: when passing variables to functions, working with arrays, and managing data dynamically (future topics).

  • A pointer’s type tells C what kind of data lives at that address (int* →\rightarrow int, float* →\rightarrow float).

  • Use the & operator to get a variable’s address, and the * operator to access the value stored there.

  • As we move forward, pointers will help us build dynamic memory, structs, and modular programs efficiently.

  • They’re one of the key ideas that make C both powerful and low-level.

Arrays and Pointers

Arrays and Pointers

In C, arrays and pointers behave similarly in many expressions, but they are not the same thing.

  • An array is a fixed block of contiguous memory that decays to a pointer to its first element when used in most expressions.

  • A pointer, on the other hand, is a separate variable that can store different addresses and move through memory.

Example

Consider the following int array

int vals[5] = {10, 20, 30, 40, 50};

vals is a fixed block of contiguous memory that holds 5 32 bit integers (32 bits = 4 bytes); each with their own addresses.

Array Names Decay to Pointers

In C, an array name is not a pointer

  • In most expressions it decays (automatically converts) to a pointer to its first element,

  • meaning the compiler automatically replaces the array name with a pointer to its first element (&array[0]).

int vals[5] = {10, 20, 30, 40, 50};
int *pVals = vals; // vals converted to &vals[0]

Array Indexing

An array name and a pointer to an array can be used interchangeably when dealt with carefully.

Example:

int vals[5] = {10, 20, 30, 40, 50};

/* Equivalent pointer values */
int *pVals = vals; // vals converts to &vals[0]
int *pVals2 = &vals[0];

In the above example, both int pointers pVals and pVals2, point to the first member of the integer array vals.

Example Continued:

int vals[5] = {10, 20, 30, 40, 50};

/* Equivalent pointer values */
int *pVals = vals; // vals converts to &vals[0]
int *pVals2 = &vals[0];

/* Equivalent indexes*/
vals[4] = 60; // Re-assigning vals[4] to 60
pVals[4] = 60;
*(vals +4) = 60;
*(pVals2 +4) = 60;

Each of the statements on lines 8 through 11 perform the same task: Re-assigning the fifth member of vals to 60.

Using printf() with Pointers

To print a memory address, use %p and write (void *) in front of the pointer:

int vals[5] = {10, 20, 30, 40, 50};
int *pVals = vals;

printf("vals (array name): %p\n", (void *)vals);
printf("&vals[0] (first): %p\n", (void *)&vals[0]);
printf("pVals (pointer var): %p\n", (void *)pVals);
printf("pVals+1 (next int): %p\n", (void *)(pVals + 1));

Output (your addresses will be different):

vals (array name): 0x7fff561b97a0
&vals[0] (first): 0x7fff561b97a0
pVals (pointer var): 0x7fff561b97a0
pVals+1 (next int): 0x7fff561b97a4

  • The first three lines print the same address; pVals + 1 is the address of the next int.

  • Never use %d or %f for addresses; only %p.

printf: Array Indexing vs. Pointer Arithmetic

Normal indexing,

printf("The first array value is %d.\n", vals[0]);
printf("The second array value is %d.\n", vals[1]);
printf("The third array value is %d.\n", vals[2]);

Indexing using pointers,

printf("The first array value is %d.\n", *(vals + 0));
printf("The second array value is %d.\n", *(vals + 1));
printf("The third array value is %d.\n", *(vals + 2));

Notes:

  • Here we are printing the values stored in memory (int), not the addresses.

  • The format specifier %d expects an int, and each expression like *(vals + i) produces an int.

  • Casting to (void *) is only required when printing the address itself with %p, not the stored value.

Bonus: Walking a 2D Array with One Pointer

Recall W6’s row-major order: a 2D array is really one flat block of memory, so grid[row][col] lives at a single offset from the start: offset=row×NUM_COLS+col\text{offset} = \text{row} \times \text{NUM\_COLS} + \text{col}

int grid[2][3] = {{1, 2, 3}, {4, 5, 6}};
int *p = &grid[0][0];   // treat the whole grid as one flat block

for (int i = 0; i < 2 * 3; i++) {
    printf("%d ", *(p + i));
}
// prints: 1 2 3 4 5 6 (the row-major order from W6)

  • p[row * NUM_COLS + col] and grid[row][col] read the exact same value

  • One loop, one pointer, no nested indices; this only works because the array is stored contiguously, in exactly that order

Arrays Are Not Pointers

An array is not equivalent to a pointer:

  • An array’s name is not a variable – it represents a fixed address in memory and cannot be reassigned.

  • A pointer is a variable that stores addresses that can be changed.

int vals1[10], vals2[10];
int *pVals1 = vals1;

vals1 = vals2;   //  Error: array names are not assignable
vals1++;      //  Error: address of vals[0] can't be changed
pVals1++;      //  Valid: stored addresses in pVals1 can change

Key idea: Arrays are fixed blocks of memory; they can’t "point" somewhere else. Pointers are flexible variables that can store different addresses.

Character Arrays and Pointers

Character Arrays and Pointers

Let’s construct two similar strings,

char name[] = "Ryan";
char *pName = "Ryan";

Since pName is a pointer variable, you can use the assignment ‘=’ operator.

pName = "Ryan B."; // allowed
name = "Ryan B."; // NOT ALLOWED

Note: C isn’t putting the new name into pName; the new name is already stored in memory, and C sets the value of the pointer pName equal to its address.
CAREFUL: There is a catch with overwriting memory which we will discuss in this week’s tutorial.

Arrays of Pointers

A common way to store an array of strings is to use pointers,

char *movies[8] = {"Amour", "Argo",
                   "Django Unchained",
                   "Les Miserables",
                   "Life of Pi", "Lincoln",
                   "Silver Linings Playbook",
                   "Zero Dark Thirty"};

for (int i = 0; i < 8; i++)
{
    printf("Have you seen %s? \n", movies[i]);
}

Summary

Summary

  • Memory is a series of numbered bytes; every variable lives at an address, usually written in hexadecimal

  • A pointer is a variable that stores an address, and its type must match what it points to

  • & gets a variable’s address; * follows a pointer to the value stored there

  • Always initialize a pointer, even if only to NULL, and check for NULL before you dereference →\rightarrow an uninitialized pointer holds garbage you can’t test for

  • An array name decays to a pointer to its first element in most expressions

  • vals[4], pVals[4], *(vals + 4) and *(pVals + 4) all reach the same element

  • Arrays are not pointers: a pointer can be changed, but an array name can’t

  • Print an address with %p and (void *)

  • char name[] holds its own copy of the letters; char *pName holds only the address of a string stored elsewhere

  • An array of char * can reach strings of different lengths

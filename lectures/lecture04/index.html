Branching

Programs Don’t Always Run Top to Bottom

Every program we’ve written so far executes every line, in order, exactly once.

Real programs need to make decisions: run this code only if some condition holds, or choose between two different pieces of code depending on the input.

This is called branching; and it is the last major flow-diagram concept before we can plan any kind of interesting program.

The Diamond: A New Shape

Recall our shapes so far: oval (Start/Stop), rectangle (process), parallelogram (input/output), connected by arrows.

This week we add a fourth shape: the diamond, for a decision.

  • It is the only shape with two arrows leaving it

  • One arrow is labeled Yes (the condition is true)

  • The other arrow is labeled No (the condition is false)

The if/else Flow Diagram Template

The Test Condition diamond splits into a true branch and a false branch, and both branches rejoin before Stop; the program continues either way.

Relational and Logical Operators

Relational Operators

A relational operator compares two values and produces a true/false result:

Operator Meaning Example
== Equal to a == b
!= Not equal to a != b
< Less than a < b
> Greater than a > b
<= Less than or equal to a <= b
>= Greater than or equal to a >= b

How C Represents True and False

C has no built-in boolean type in the classic sense;

  • Zero is false.

  • Any non-zero value is considered true.

A relational operator produces a 1 or 0:

int a = (4 < 10);  // (4 < 10) is true, so a = 1
int b = (8 == 9);  // (8 == 9) is false, so b = 0

C99 gives you named values via <stdbool.h>:

#include <stdbool.h>
bool x = false;   // x is really just 0
bool y = true;    // y is really just 1

Logical Operators

Logical operators combine multiple conditions into one:

Operator Meaning
&& And – both sides must be true
|| Or – either side (or both) must be true
! Not – reverses true/false

Example: check if age is within working age, 21 to 65:

if (age >= 21 && age <= 65) {
    printf("Working age.\n");
}

Truth Tables

&& (And)

A B A && B
T T T
T F F
F T F
F F F

|| (Or)

A B A || B
T T T
T F T
F T T
F F F

! simply flips the result: !(A) is true exactly when A is false.

The if Statement

The if Statement

General format:

if (condition) {
    statement 1;
    statement 2;
    ...
}

The block executes only if condition evaluates to true (non-zero).

if (temperature > 30) {
    printf("It's hot today.\n");
}

The else Statement

else supplies the branch to take when the condition is false:

if (condition) {
    statement 1;
    ...
} else {
    statement 1;
    ...
}

Exactly one of the two blocks executes; never both, never neither.

The else if Chain

Multiple conditions, checked in order:

if (condition1) {
    ...
} else if (condition2) {
    ...
} else if (condition3) {
    ...
} else {
    ...
}

The computer picks the first branch whose condition matches and skips the rest; even if a later condition would also be true.

= vs. ==

The Classic Bug: = vs. ==

= assigns; == compares. Mixing them up is one of the most common bugs in C.

int isCharterMember = 0;

if (isCharterMember = 1) {   
// BUG: this ASSIGNS 1, doesn't compare!
    printf("Welcome back!\n");
}
Sample run
Welcome back!

isCharterMember = 1 is itself an expression whose value is 1, which is non-zero, so the if is always true, no matter what isCharterMember held before.

if (isCharterMember == 1) {   // correct: COMPARES
    printf("Welcome back!\n");
}

Why this is dangerous: the code compiles; the compiler won’t save you here (though -Wall will warn you).

The switch Statement

The switch Statement

A long else if chain testing the same variable against many values gets hard to read:

if (day == 1) { printf("Mon\n"); }
else if (day == 2) { printf("Tue\n"); }
else if (day == 3) { printf("Wed\n"); }
// ... and so on

switch is an efficient multi-way branch on a single integer or character value:

switch (day) {
    case 1: printf("Mon\n"); break;
    case 2: printf("Tue\n"); break;
    case 3: printf("Wed\n"); break;
    default: printf("Invalid\n");
}

switch: Anatomy

switch (expression) {
    case value1:
        statements;
        break;
    case value2:
        statements;
        break;
    default:
        statements;
}

  • expression must evaluate to an int or char

  • Control jumps to the matching case label

  • default runs when no case matches; like a final else

  • default is optional, but good practice

break: Why It Matters

Without break, execution falls through into the next case, ignoring its label:

switch (day) {
    case 1: printf("Mon\n");   // no break!
    case 2: printf("Tue\n");   // no break!
    case 3: printf("Wed\n"); break;
    default: printf("Invalid\n");
}
Sample run · with int day = 1;
Mon
Tue
Wed

If day == 1, this prints all three: Mon, Tue, and Wed; execution keeps running until it hits a break or the end of the switch.

Fall-Through: A Bug, or On Purpose?

Usually, missing break is a bug.

But fall-through can be intentional; grouping several cases that should do the same thing:

switch (grade) {
  case 'A':
  case 'B':
  case 'C':
    printf("Passing\n");
    break;
  case 'D':
  case 'F':
    printf("Failing\n");
    break;
}
Sample run · with char grade = 'B';
Passing

Here, case 'A': and case 'B': have no statements of their own. They intentionally fall through to case 'C':’s code. Comment intentional fall-through so the next reader doesn’t "fix" it.

switch vs. else if: When to Prefer Which

  • Use switch when testing one variable against many exact integer/character values

  • Use if/else if when conditions involve ranges, multiple variables, or relational/logical operators; switch cannot test score >= 90

  • switch often reads more clearly for menu-style or command-style branching

Summary

Summary

  • The diamond: the only shape with two arrows →\rightarrow True and False

  • Relational operators produce a true (1) or false (0) result; logical operators (&&, ||, !) combine conditions

  • if/else if/else: the computer picks the first matching branch and skips the rest

  • = assigns, == compares →\rightarrow this bug compiles silently

  • switch: efficient multi-way branch on an int/char; break prevents fall-through; fall-through can be intentional if commented

  • Prefer switch for exact-value branching on one variable; prefer if/else if for ranges and multi-variable conditions

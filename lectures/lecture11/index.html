Week 6: Arrays; Declaration and Indexing

  • A string was already an array of char , and the same idea generalizes to any type

  • Declaration reserves contiguous memory for N elements, all of the same type

  • Indexing starts at 0: for an array of size N, valid indices run from 0 to N-1

  • C performs no bounds checking →\rightarrow reading or writing outside 0..N-1 is undefined behavior, not a compile error

int marks[30];      // valid indices: 0 .. 29
marks[0]  = 85;      // first element
marks[29] = 77;      // last element
marks[30] = 100;     // BUG: one past the end

Week 6: Arrays; Initializing and Iterating

int scores[5] = {90, 85, 77, 60, 100};
int sum = 0;

for (int i = 0; i < 5; i++) { 
  // i < 5, NOT i <= 5
    sum += scores[i];
}
double average = sum / 5.0;

  • Listing fewer initializers than the declared size zero-fills the rest: {90, 85} in a size-5 array gives {90, 85, 0, 0, 0}

  • Standard traversal pattern: start at i = 0, stop before i reaches the size (i < N) →\rightarrow this is exactly what keeps you in bounds

Week 6: Two-Dimensional Arrays

int grid[2][3];   // 2 rows, 3 columns

for (int row = 0; row < 2; row++) {
    for (int col = 0; col < 3; col++) {
        printf("%d ", grid[row][col]);
    }
}

  • C stores a 2D array as one contiguous strip of memory, laid out row by row; row-major order

  • Traversal order: grid[0][0], grid[0][1], grid[0][2], grid[1][0], …\ldots

  • Outer loop selects the row, inner loop sweeps across that row’s columns, the same nested-loop pattern as earlier weeks

Week 6: Strings and <string.h>

char city[] = "Nelson";        // 6 letters + '\0'
printf("%lu\n", strlen(city)); // 6: '\0' not counted
printf("%lu\n", sizeof(city)); // 7: '\0' included

  • A string is a char array that ends with the null terminator '\0'; every string function walks until it finds one

  • strcpy, strcat, strcmp: copy, append, compare. None of them checks that the destination is big enough

  • fgets(s, sizeof(s), stdin) reads a whole line safely; scanf("%s", s) stops at the first space (and takes no &: the array name is already an address)

Week 8: Decomposition and the Function-Call Box

  • Decomposition: break a large task into smaller, named subtasks. This is the core habit of software design

  • A rectangle with a bar at each end is a function call; the dashed box still means only “loop body”

  • Its internals (Input/Process/Output/Decision shapes) live in a separate diagram

Week 8: Function Anatomy and Prototypes

return_type function_name( parameter list ) {
    // body
    return value;
}

  • Every function must be declared before it is used; a prototype lets the compiler check a call before it sees the full definition

  • void return type →\rightarrow no value returned; void parameter list →\rightarrow no arguments

  • Argument = value passed at the call site; parameter = the name used in the definition

Week 8: Pass-by-Value

  • C always copies the argument into the parameter →\rightarrow a function cannot change the caller’s variable this way

void addOne(int n);

int main() {
    int x = 5;
    addOne(x);
    printf("%d\n", x); // still 5
}

void addOne(int n) {
    n = n + 1;        // changes only the copy
}

Week 8: Scope and Storage Duration

  • Local scope: inside a function; block scope: inside a pair of braces; global scope: outside all functions, visible everywhere in the file

  • Each function call gets its own private set of local variables. This is why one function can’t see another’s variables

  • Globals create hidden connections between functions; prefer parameters and return values

  • static locals are created once and persist between calls, instead of being destroyed when the block ends

void count_calls(void) {
    static int calls = 0;  // initialized once
    calls++;
    printf("Called %d time(s)\n", calls);
}

Week 9: Addresses, &, and *

  • Every variable lives at a specific address in memory

  • A pointer is a variable whose value is an address: it “points to” another variable

  • & produces the address of a variable; * dereferences a pointer →\rightarrow follows it to the value at the other end

int age = 19;
int *pAge = &age; // pAge holds the address of age
*pAge = 25; // writes through the pointer: age is 
            // now 25

Week 9: Memory Diagrams and NULL

  • Draw boxes for variables (name, address, value); arrows for pointer relationships. This is the essential tool for reasoning about pointers

  • NULL: a pointer that points to nothing; always check before dereferencing:

    if (p != NULL)

Week 9: Arrays Decay to Pointers

int vals[5] = {10, 20, 30, 40, 50};
int *pVals = vals;  // vals decays to &vals[0]

vals[4] = 60;
*(pVals + 4) = 60;  // pointer arithmetic;
                    // same element

  • An array name decays to a pointer to its first element in most expressions

  • *(pVals + i) reaches the same element as vals[i]

  • But an array name is not a variable →\rightarrow it can’t be reassigned (vals++ is an error; pVals++ is fine)

Week 9: Walking an Array with a Pointer

int vals[4] = {3, 1, 4, 1};
int *p = vals;         // p points at vals[0]

for (int i = 0; i < 4; i++) {
    printf("%d ", *p); // the value p points at
    p++;              // move to the next element
}

  • p++ moves the pointer one element along, not one byte; for an int array that is 4 bytes

  • The same walk works on a string: start at the first char and stop when *p is '\0'

Week 9: char [] vs. char *

char name[]  = "Ada"; // an array you own: 4 chars
char *pName  = "Ada"; // points to a string in
                      // read-only memory

pName = "Grace"; // allowed: pName is a variable
name  = "Grace"; // ERROR: an array name can't be
                 // assigned
                 
strcpy(name, "Bo"); // copy INTO the array instead
pName[0] = 'B';     // CRASH: can't change read-only
                    // memory

  • An array name is a fixed address; a pointer is a variable that can hold a different address later

  • An array of strings is usually an array of pointers: char *days[3] = {"Mon", "Tue", "Wed"};

Week 9: Two Pointers, Two Variables

The next two slides both start from these three lines:

int m = 1, n = 5;
int *p = &m;
int *q = &n;

p holds the address of m; q holds the address of n.

Week 9: Copying an Address

p = q;   // no *: changes where p points

q’s address is copied into p, so now p and q both point at n. m is still 1.

Week 9: Copying a Value

*p = *q; // with *: changes the variable p points at

The value at q (5) is copied into the variable at p, so m is now 5. p still points at m.

Rule: without a *, you change where a pointer points; with a *, you change the variable it points at.

Practice Problems

Problem 1: Array Bounds

What is wrong with this code?

int scores[10];
for (int i = 0; i <= 10; i++) {
    scores[i] = 0;
}

Solution 1: Array Bounds

int scores[10];
for (int i = 0; i <= 10; i++) { 
    // BUG: i reaches 10
    scores[i] = 0;
}

Valid indices for scores[10] run 0 to 9. When i is 10, scores[10] writes one element past the end of the array →\rightarrow undefined behavior, not a compile error. Fix: i < 10.

Problem 2: Used Before Declared

Why does this fail to compile?

int main() {
    int result = square(5);
    printf("%d\n", result);
}

int square(int n) {
    return n * n;
}

Solution 2: Used Before Declared

int square(int n);   // FIX: prototype before main()

int main() {
    int result = square(5);
    printf("%d\n", result);
}

int square(int n) {
    return n * n;
}

The compiler hasn’t seen anything about square (not a prototype, not a definition) by the time main() calls it. A prototype above main() fixes this regardless of where the definition appears later.

Problem 3: Pass-by-Value

What does this print?

void triple(int n);

int main() {
    int x = 5;
    triple(x);
    printf("%d\n", x);
}

void triple(int n) {
    n = 3*n;
}

Solution 3: Pass-by-Value

void triple(int n) {
    n = 3*n;   // changes only the local copy
}

Prints 5, not 15. n is a copy of x; C always passes by value. Fix, if a new value is wanted, return it:

int triple(int n) { 
    return 3*n; 
}

and store it with x = triple(x);.

Problem 4: Missing NULL Check

What happens when this runs?

int *p = NULL;
printf("%d\n", *p);

Solution 4: Missing NULL Check

int *p = NULL;
printf("%d\n", *p);   // no NULL check!

Segmentation fault: *p dereferences an address that points nowhere valid, and the OS kills the program immediately. Fix:

if (p != NULL) { 
  printf("%d\n", *p); }

Always check before dereferencing.

Problem 5: 2D Array Traversal

What is wrong with this code, meant to print a 3×23\times2 grid (3 rows, 2 columns)?

int grid[3][2] = {{1,2},{3,4},{5,6}};
for (int row = 0; row < 2; row++) {
    for (int col = 0; col < 3; col++) {
        printf("%d ", grid[row][col]);
    }
}

Solution 5: 2D Array Traversal

int grid[3][2] = {{1,2},{3,4},{5,6}};
for (int row = 0; row < 2; row++) {   
  // BUG: swapped bounds
    for (int col = 0; col < 3; col++) {
        printf("%d ", grid[row][col]);
    }
}

The outer loop bound must match the row count (3) and the inner loop bound must match the column count (2); they were swapped. This both misses row 2 entirely and reads grid[0][2]/grid[1][2], which are out of bounds. Fix: row < 3 outer, col < 2 inner.

Problem 6: Pointer Arithmetic

What does this print?

int vals[5] = {10, 20, 30, 40, 50};
int *p = vals + 1;

printf("%d %d\n", *p, *(p + 2));
p++;
printf("%d %d\n", *p, vals[4] - *p);

Solution 6: Pointer Arithmetic

20 40
30 20

  • vals + 1 is the address of vals[1], so *p is 20 and *(p + 2) is vals[3], 40

  • After p++, p points at vals[2]: *p is 30, and 50−30=2050 - 30 = 20

  • *(p + i) counts i elements from wherever p points now

Problem 7: static Local Variables

How many times does this print, and what values?

void count_calls(void);

int main() {
    count_calls();
    count_calls();
    count_calls();
}

void count_calls(void) {
    static int calls = 0;
    calls++;
    printf("%d\n", calls);
}

Solution 7: static Local Variables

Prints 1, 2, 3, not 1, 1, 1. calls is initialized to 0 only on the first call; every later call reuses the same calls instead of resetting it, because a static local persists between calls instead of being destroyed when the function returns.

Problem 8: What Do I Do?

This function has no useful name.

int what_do_i_do(int n) {
    int x = 1;
    while (x * x <= n) {
        x++;
    }
    return x - 1;
}

For the call what_do_i_do(30):

  1. What does it return?

  2. In one sentence, what does the function do?

  3. What are its parameters and its local variables?

  4. Suggest a better name.

Solution 8: What Do I Do?

  1. Returns 5. x counts up while x * x <= 30: 5×5=255 \times 5 = 25 passes, 6×6=366 \times 6 = 36 fails, so the loop stops at 6 and returns 6−16 - 1.

  2. It finds the largest whole number whose square is at most n: the whole-number square root.

  3. Parameter: n. Local variable: x.

  4. int_sqrt(..)

Tip: trace it with a small input first, writing down each variable’s value on every pass, then look for the pattern.

Problem 9: Flow Diagram with a Function Call

The function from Problem 8, renamed int_sqrt(n), is ready to use. Draw the top-level flow diagram for this program:

  • It has an array int nums[5] = {16, 20, 49, 50, 81};

  • For each element, it calls int_sqrt() once and saves the result in r

  • If r * r equals the element, it prints the element (a perfect square)

Use a for loop, a function-call box, and a dashed box around the loop body. What does the program print?

Solution 9: Flow Diagram with a Function Call

  • The call box saves the result:
    r = int_sqrt(nums[i])

  • The decision uses r, so the function is called only once per element

  • The top level doesn’t show how int_sqrt works. That is its own diagram

Prints 16 49 81.

Problem 10: A 2D Array Through a Pointer

What does this print?

int seats[2][4] = {{3, 0, 5, 1},
                   {2, 6, 0, 4}};
int *p = &seats[0][0];

printf("%d %d\n", *(p + 5), *(p + 1 * 4 + 3));

Solution 10: A 2D Array Through a Pointer

Output:

6 4

  • In memory, seats is one strip, row by row: 3 0 5 1 2 6 0 4

  • seats[row][col] is at offset row×4+col\text{row} \times 4 + \text{col} from p, because each row holds 4 elements

  • Offset 5 is 1×4+11 \times 4 + 1: seats[1][1], which is 6

  • *(p + 1 * 4 + 3) is offset 7: seats[1][3], which is 4

Problem 11: One Loop Instead of Two

This prints seats from Problem 10, one row per line:

for (int r = 0; r < 2; r++) {
    for (int c = 0; c < 4; c++) {
        printf("%d ", seats[r][c]);
    }
    printf("\n");
}

Rewrite it as a single loop (no nested loops) that reads every element through int *p = &seats[0][0]; and prints exactly the same two lines.

Solution 11: One Loop Instead of Two

int *p = &seats[0][0];
for (int i = 0; i < 2 * 4; i++) {
    printf("%d ", *(p + i));
    if ((i + 1) % 4 == 0) {  // a full row printed
        printf("\n");
    }
}

  • One loop visits all 2×4=82 \times 4 = 8 elements in memory order

  • i + 1 is how many elements have been printed so far. When it is a multiple of 4, a whole row is done: print the newline there

Problem 12: Walking a String with a Pointer

What does this print? (<ctype.h> is included.)

char sign[] = "Rm 204B, Bldg 7!";
char *p = sign;
int upper = 0, punct = 0;

while (*p != '\0') {
    if (isupper(*p))
        upper++;
    if (ispunct(*p))
        punct++;
    p++;
}
printf("%d %d\n", upper, punct);

Solution 12: Walking a String with a Pointer

Output:

3 2

  • Upper case: 'R', the 'B' in 204B, and the 'B' in Bldg

  • Punctuation: ',' and '!'; digits and spaces count as neither

  • *p is the character p points at; p++ moves to the next one

  • The loop stops at the '\0', which is never counted

Problem 13: A Pointer Walk in Memory

(<ctype.h> is included.)

char word[] = "pin";
char *p = word;

while (*p != '\0') {
    *p = toupper(*p);
    p++;
}
printf("%s\n", word);

  1. Draw the memory diagram after line 2. word starts at 0x7ffe20, and p is at 0x7ffe28.

  2. Redraw it after each pass of the loop.

  3. Where does p point when the loop ends? What is printed?

Solution 13: A Pointer Walk in Memory

After line 2: each char takes 1 byte, so the addresses go up by 1. p holds 0x7ffe20, the address of word[0].

Pass 1: *p = toupper(*p) changes 'p' to 'P', then p++ moves p one byte to word[1].

Pass 2: 'i' becomes 'I', and p moves to word[2].

Pass 3: 'n' becomes 'N', and p moves to word[3].

Now *p is '\0', so the loop stops with p pointing at the null terminator. Prints PIN.

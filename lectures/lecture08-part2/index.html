Scope

Variables and Scope

What is scope?

  • The scope of a variable is the region of a program where that variable can be seen or used

  • Once execution leaves that region, the variable no longer exists or cannot be accessed

Local vs. Global Variables

  • A variable declared inside a function or block of code (between braces) is local to that block

  • Local variables are created when the block starts and destroyed when it ends

  • A variable declared outside of all functions is global →\rightarrow it can be accessed and modified by any function in the same file

  • Global variables exist for the entire lifetime of the program

Example: Visibility of Variables

#include <stdio.h>

void test(void);

int main(void) {
    int a = 10; // main's own variable
    printf("main: a = %d\n", a);
    test();
    printf("test: b = %d\n", b);
    return 0;
}

void test(void) {
    int b = 20; // test's own variable
    printf("test: b = %d\n", b);
}

Compiler output:

line 9: error: 'b' undeclared
(first use in this function)

Key Ideas:

  • a can be used only inside main().

  • b can be used only inside test().

  • Line 9 uses b inside main(), so the program doesn’t compile.

Example: Local Variables With the Same Name

#include <stdio.h>

void add_ten(void);
void add_hundred(void);

int main(void) {
    add_ten();
    add_hundred();
    add_ten();
    return 0;
}

void add_ten(void) {
    int x = 0; // local
    x = x + 10;
    printf("add_ten:     x = %d\n", x);
}

void add_hundred(void) {
    int x = 0; // local
    x = x + 100;
    printf("add_hundred: x = %d\n", x);
}

Output:

add_ten:     x = 10
add_hundred: x = 100
add_ten:     x = 10

Key Ideas:

  • Each function has its own x.

  • Changing x in add_ten() does not affect x in add_hundred().

  • The second add_ten() prints 10, not 20: its x starts over at 0.

  • Each call gets its own private set of local variables.

Example: Global Scope

#include <stdio.h>

int x = 0; // global variable

void add_ten(void);
void add_hundred(void);

int main(void) {
    add_ten();
    add_hundred();
    add_ten();
    return 0;
}

void add_ten(void) {
    x = x + 10;
    printf("add_ten:     x = %d\n", x);
}

void add_hundred(void) {
    x = x + 100;
    printf("add_hundred: x = %d\n", x);
}

Output:

add_ten:     x = 10
add_hundred: x = 110
add_ten:     x = 120

Key Ideas:

  • x is declared outside all functions →\rightarrow global scope: every function can see and change it.

  • No function declares its own x, so they all share one x.

  • The second add_ten() prints 120, not 10: it adds to what add_hundred() left behind.

Why Global Variables Are Usually a Bad Idea

Globals feel convenient; no need to pass anything around. But they create hidden connections between functions:

  • Any function can change a global at any time →\rightarrow there’s no record of who touched it, or when

  • Reading a function’s code no longer tells you everything it depends on →\rightarrow you have to check every other function too

  • Bugs caused by an unexpected global change are some of the hardest to track down, because the change could have come from anywhere in the file

Prefer passing values as parameters and returning results →\rightarrow keep a function’s dependencies visible in its signature.

Example: Scope Errors

#include <stdio.h>

void print_square(void);

int main(void) {
    int x = 5; // local to main
    print_square();
    printf("Done!\n");
    return 0;
}

void print_square(void) {
    int result = x * x; // 'x' not visible here
    printf("Square = %d\n", result);
}

Compiler output:

error: 'x' undeclared (first use in this function)
    int result = x * x;
                 ^

Declare x outside all functions instead:

#include <stdio.h>

int x = 5; // global variable

void print_square(void);

int main(void) {
    print_square();
    printf("Done!\n");
    return 0;
}

void print_square(void) {
    int result = x * x; // 'x' is now visible (global)
    printf("Square = %d\n", result);
}

Output:

Square = 25
Done!

Example: Block Scope

#include <stdio.h>

int main(void) {
    int total = 0;

    for (int i = 1; i <= 3; i++) {
        int square = i * i;
        total += square;
    }

    printf("total = %d\n", total);
    // printf("%d", square); invalid
    // printf("%d", i);      invalid
    return 0;
}

Output:

total = 14

Key Ideas:

  • Any pair of braces makes a block; a variable declared inside one exists only inside it.

  • square and the loop’s i are gone after the loop’s closing brace (line 9).

  • total is declared in main()’s own block, so it can be used inside the loop and after it.

Storage Duration and static

Storage Duration

Scope tells you where a variable can be seen. Storage duration tells you how long it exists.

  • By default, a local variable is created when its block starts and destroyed when the block ends →\rightarrow every call to a function starts with fresh, uninitialized locals

  • A static local variable is different: it is created once, keeps its value between calls, and is only destroyed when the program ends

Example: A static Call Counter

#include <stdio.h>

void count_calls(void);

int main(void) {
    count_calls();
    count_calls();
    count_calls();
    return 0;
}

void count_calls(void) {
    static int calls = 0; 
    // initialized once
    calls++;
    printf("Called %d time(s)\n", calls);
}

Output:

Called 1 time(s)
Called 2 time(s)
Called 3 time(s)

Key Ideas:

  • calls is initialized to 0 only on the first call.

  • Every later call reuses the same calls; an ordinary local would reset to 0 every time.

  • This is what "persists between calls" means.

Run count_calls() three times, with calls declared static and then as an ordinary local:

Why This Matters: Private Locals, Revisited

Put scope and storage duration together, and you get the rule this whole section has been building toward:

Each function call gets its own private set of local variables, completely separate from every other call (to that same function, or to any other). static is the one exception: it opts a single variable out of "destroyed when the block ends," without changing who can see it.

This is exactly why add_ten()’s x and add_hundred()’s x didn’t collide earlier, and why two calls to the same function never interfere with each other, either.

Summary

Summary

  • Decomposition: break a large task into smaller, named subtasks

  • A function is a contract: given these inputs (parameters), produce this output (return value)

  • Prototypes let the compiler check a call before it sees the definition →\rightarrow declare every function you call before main()

  • Pass-by-value: C always copies the argument into the parameter; a function can’t change the caller’s variable this way

  • The function-call box (rectangle with a bar at each end): a function call in a top-level diagram, whose internals live in a separate diagram

  • Scope: local, block, and global, and why globals create hidden, hard-to-debug connections

  • Storage duration: locals die with their block; static locals persist between calls

  • Each call gets its own private locals →\rightarrow this is why one function can’t see another’s variables

How a Computer Runs a Program

What Does a Computer Actually Do?

At its core, a computer is a machine that executes instructions, one at a time.

  • Each instruction is extremely simple: add two numbers, copy a value, compare two values, jump to a different instruction.

  • Nothing happens “all at once”; everything is one step after another.

How Computers Read Instructions?

The CPU (Central Processing Unit) is the physical piece of hardware that reads one instruction, carries it out, then moves to the next.

Photo: Eric Gaba, CC BY-SA 4.0, via Wikimedia Commons

The instructions that a CPU reads are called Machine Code (also known as "native code").

Machine Code

  • Machine code is hardwired into the design of the CPU hardware; it can’t be changed at will

  • Each family of compatible CPUs (e.g. the popular Intel x86 family) has its own, idiosyncratic machine code

  • Machine code from one CPU family is not compatible with another family’s

What is a Program?

A program is just a very long, very precise list of these simple instructions.

An example of a program is the web browser Firefox,

Logo: Mozilla Foundation, MPL 2.0, via Wikimedia Commons. Firefox is a trademark of the Mozilla Foundation.

  • it is made up of a sequence of millions of these very simple machine code instructions,

  • each of these instructions are as simple as just adding or comparing two numbers.

The Mental Model: Input →\to Process →\to Output

Almost every program you write this term can be described with one simple pattern:

  • Input; the program receives data (from the keyboard, a file, etc.)

  • Process; the program does something with that data (calculations, comparisons, ...)

  • Output; the program produces a result (text on the screen, a file, ...)

We will keep coming back to this pattern all semester; today, our first programs will only have the Output step.

Source Code

Source Code: Instructions for Humans and Machines

Source code is the text you write; it is written so that a human can read and understand it.

  • The computer cannot run your source code directly.

  • It must first be translated into instructions the CPU understands.

  • How that translation happens depends on the language.

Many Languages, Many Grammars

Just like English and French have different grammar rules, every programming language has its own grammar (or syntax); the rules for how code must be written.

  • C, Python, Java, and JavaScript all look different and follow different rules, even when solving the same problem

  • Each language’s translator only understands that language’s grammar; a C compile (translator) can’t read Python

  • And each language has its own way of getting translated into machine code

Compiled vs. Interpreted Languages

Compiled languages (e.g. C, C++): your entire source file is translated ahead of time into a standalone executable program.

  • You run the translator (the compiler) once

  • The result is a file the CPU can run directly, any time, without the compiler

Interpreted languages (e.g. Python, JavaScript): another program (the interpreter) reads your source code and carries out its instructions as it reads them, line by line, every time you run it.

C Programming Language

C Programming Language

This term we will be writing our programs in C, which is a compiled language; your text file becomes a runnable program.

Note: the source code in the image above is not actual C syntax; it just illustrates the general idea of source code being compiled (translated) into machine code.

History of C

  • Developed at Bell Laboratories by Ken Thompson and Dennis Ritchie (1972)

  • General-purpose

  • Fast

  • Adaptable

Photo: unknown author, public domain, via Wikimedia Commons

Versions of C

  • Early C (“K&R C”): described by Kernighan and Ritchie’s 1978 book, before any official standard

  • ANSI C (1989, aka C89/C90): first official standard, from the American National Standards Institute

    • Standardized function prototypes and the standard library

    • Made C code portable across different compilers

  • Later standards refined the language: C99, C11, C17, C23

  • In this course, “ANSI C” just means standard, portable C

Influence of C today

  • Unix and Most of Linux written in C

  • Databases (SQL, Oracle) written in C

  • Other programming languages, (e.g. Python) use compilers or interpreters written in C.

  • Influenced C++, Objective-C, C#, Carbon etc.

Photo: unknown author, public domain, via Wikimedia Commons

The Development Cycle

Every week this term, you will repeat the same four-step cycle:

Write →\to Compile →\to Run →\to Observe

  • Write; edit your source code in an editor

  • Compile; translate it into a program; fix any errors the compiler reports

  • Run; execute the resulting program

  • Observe; check the output against what you expected; if it’s wrong, go back to Write

A Minimal C Program

The Building Blocks

Every C program we write this term starts with the same four pieces:

  • #include <stdio.h>; brings in printf (allows you to print characters to the screen) and friends before the rest of the program is compiled

  • main(); where the program starts running; everything between its opening { and closing } runs first, top to bottom

  • the semicolon ; →\to ends every statement; leave one out and the compiler will complain

  • return 0; →\to the last statement in main(); it tells the operating system the program finished successfully and ends the program

    #include <stdio.h>
    int main()
    {
      printf("...");
      return 0;
    }

Our First C Program

Below is a simple C program saved in the source file small_step.c.

/* Prints a message on the screen */
#include <stdio.h>
int main()
{
  printf("Just one small step for coders. ");
  printf("One giant leap for programmers!\n");
  return 0;
}
Sample run
Just one small step for coders. One giant leap for programmers!


This is the simplest complete C program: it compiles, runs, and produces output.

What Does printf() Do?

printf() is a library function that sends text to the screen ; it is our first Output step.

  printf("Just one small step for coders. ");
  printf("One giant leap for programmers!\n");

  • The text inside the quotes is printed exactly as written

  • \n means “start a new line”

  • You can call printf() as many times as you like; each call is its own output step

Comments

Comments are not C instructions; the compiler ignores them. They explain your code to other humans (and to future you).

  /* Prints a message on the screen */

Two types of comments:

  // This is a single-line comment

  /* This is a
   multi-line comment */

Use comments to explain why, not to restate what the code obviously already says.

Flow Diagrams

Planning Before Coding

Before we write any more code, let’s learn a tool for planning programs: a flow diagram (or flowchart).

  • A flow diagram is a picture of the steps a program takes, and the order it takes them in

  • It lets us plan the logic of a program before typing any code

  • Each shape has a specific meaning

  • Arrows show the order things happen

This is the first time we use flow diagrams; we’ll keep extending them all course.

Flow Diagram Shapes (This Week)

This week we only need three shapes, plus the arrow:

  • Oval; Start or Stop of the program

  • Rectangle; a process or computation step

  • Parallelogram; input or output (e.g. printf(), scanf())

We will see two more shapes (decision, and grouped-logic) later in the course, once we start writing if statements and loops.

Mapping Input →\to Process →\to Output onto Shapes

Recall today’s mental model: every program reads input, processes it, and produces output.

For a program that only prints a message, there is no input or processing step; just output:

Computing Environments

Computing Environments

Computing Environment: the collection of hardware, software, and tools needed to write, compile, and run programs.

Examples:

  • Our labs: Windows, with gcc (GNU C Compiler), VS Code, and PowerShell

  • A Mac with Xcode and Terminal

  • There are other computing environments too, e.g. for web development, data science, or supercomputers

Compilers

Compiler: a program that translates your source code into an executable program.

Examples of C compilers:

  • gcc (GNU C Compiler, Linux and most labs)

  • Xcode’s compiler (Mac)

  • MinGW / Cygwin (GNU compiler for Windows)

Command Line Interface (CLI)

CLI: a way of interacting with the computer by typing text commands instead of clicking.

  • Terminal (Mac/Linux)

  • Windows PowerShell; what we’ll use in this course

We compile and run our programs from the CLI.

Writing Code: the Editor / IDE

An Integrated Development Environment (IDE) helps you:

  • organize code and projects

  • catch syntax mistakes as you type

  • compile and run your program with one click

We will use VS Code with the C/C++ extension.

Compiling and Running From the CLI

Assume you have a file small_step.c.

  • Open a CLI: PowerShell (Windows) or Terminal (Mac/Linux)

  • Navigate to the folder containing the file

  • Compile:
    gcc small_step.c -o small_step.exe (Windows)
    gcc small_step.c -o small_step.out (Mac)

  • This creates an executable file

  • Run it:
    ._step.exe (Windows)
    ./small_step.out (Mac)

  • The program runs and prints its output in the same CLI window

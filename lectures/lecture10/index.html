Pass-by-Reference

Recall: Pass-by-Value

Look back to the lecture on functions and scope: a function only ever receives a copy of its argument.

void addOne(int n);

int main() {
    int x = 5;
    addOne(x);
    printf("%d\n", x);  // still 5
}

void addOne(int n) {
    n = n + 1;   // changes the copy, not x
}

This is fine for reading a value; but it means a function cannot modify a variable back in the caller. What if we need it to?

Fixing addOne()

Pass the variable’s address instead, and the function can reach the original:

void addOne(int *n);

int main() {
    int x = 5;
    addOne(&x);
    printf("%d\n", x);  // now 6
}

void addOne(int *n) {
    *n = *n + 1;   // follows n to x itself
}

  • addOne(&x) passes the address of x, so n points to x

  • *n is x itself, so the change is still there after addOne() returns

Pass-by-Reference

Pass-by-reference: hand a function a variable’s address instead of a copy of its value, so the function can reach and change the original.

Pass-by-value Pass-by-reference
Parameter int n int *n
Call addOne(x) addOne(&x)
The function gets a copy of the value the address of x
Can it change x? no yes, through *n

C still copies the argument; with pass-by-reference the copy is an address, and that address leads back to the original.

Two Different Places, Two Different Rules

The * and & go in two different places, and each one has its own job:

void addOne(int *n);

int main() {
    int x = 5;
    addOne(&x);
}

void addOne(int *n) {
    *n = *n + 1;
}

  • Signature, int *n: the * is part of the type. It says “n is a pointer to an int”. The prototype and the definition both say it.

  • Call, &x: & gets the address of x, and that address is copied into n.

  • Body, *n: here * follows the pointer to the int at the other end.

Quick Summary: Pointers and Functions

Three places, three jobs:

Where Write What it does
Function signature void addOne(int *n) n is a pointer to an int
Function call addOne(&x) passes the address of x
Function body *n = *n + 1; follows n to change x

Pointer in the signature, address in the call, dereference in the body.

Swapping Two Variables

Swapping Two Variables

A common job: exchange the values of two variables. If x is 3 and y is 7, we want x to end up 7 and y to end up 3.

The obvious way fails:

x = y;  // x is now 7
y = x;  // y is still 7

the 3 is lost!

Save one value first:

int temp = x;  // temp is 3
x = y;         // x is now 7
y = temp;      // y is now 3

We’ll want to do this often, so let’s write a function called swap(). It has to change two of the caller’s variables, so a single return value can’t do the job.

The Broken swap(): The Function

First, let’s put those three lines in a function, without pointers:

void swap(int a, int b) {
  int temp = a;
  a = b;
  b = temp;
  printf("Inside swap: ");
  printf("a = %d, b = %d\n", a, b);
}

  • int a, int b: the parameters receive copies of the caller’s values

  • The body starts with the same three lines as before

  • The two printfs show a and b, so we can see inside

The Broken swap(): Calling It

#include <stdio.h>

void swap(int a, int b);  // defined after main()

int main() {
  int x = 3, y = 7;
  printf("Before: x = %d, y = %d\n", x, y);
  swap(x, y);
  printf("After:  x = %d, y = %d\n", x, y);
  return 0;
}

Output:

Before: x = 3, y = 7
Inside swap: a = 7, b = 3
After:  x = 3, y = 7

  • Inside, a and b are swapped

  • But they are copies, like n in the first addOne()

  • Back in main(), x and y are unchanged

Fixing swap(): The Function

The fix is the same as for addOne(): make the parameters pointers.

void swap(int *a, int *b) {
  int temp = *a;
  *a = *b;
  *b = temp;
  printf("Inside swap: ");
  printf("*a = %d, *b = %d\n", *a, *b);
}

  • int *a, int *b: the parameters are pointers to the caller’s variables

  • The same three lines, with * in front of a and b

  • *a and *b swap the caller’s variables, not copies

Fixing swap(): Calling It

#include <stdio.h>

void swap(int *a, int *b);  // defined after main()

int main() {
  int x = 3, y = 7;
  printf("Before: x = %d, y = %d\n", x, y);
  swap(&x, &y);
  printf("After:  x = %d, y = %d\n", x, y);
  return 0;
}

Output:

Before: x = 3, y = 7
Inside swap: *a = 7, *b = 3
After:  x = 7, y = 3

  • As with addOne(), swap(&x, &y) passes addresses

  • *a and *b reach main()’s x and y

  • Pass-by-reference again, with two variables

Inside swap(), just before it returns:

How it got there, one line at a time:

  1. On entry: a and b are swap()’s own boxes, holding the addresses of x and y. temp has no value yet.

  2. int temp = *a; follows a to x and copies its 3 into temp.

  3. *a = *b; follows b to y, then writes its 7 through a into x. For a moment both hold 7; the 3 survives only in temp.

  4. *b = temp; writes the saved 3 through b into y. x and y are swapped.

Same two boxes, same addresses; only what’s inside them changed. swap() wrote through the pointers it received while it was running; once it returns, its own locals (a, b) are gone, but the change to main’s x and y stays behind.

Passing Arrays to Functions

Passing Arrays to Functions

In C, arrays are always passed to functions by reference; the function receives the address of the first element, not a copy of the whole array.

Important points:

  • You do not need the & operator when passing an array; the array’s name already decays to the address of its first element (recall Lecture 9).

  • Inside the function, the parameter acts as a pointer to the array.

  • Any changes made to array elements inside the function affect the original array in main(); no pointer trick required, unlike a plain int.

  • The flip side: since the parameter is just a pointer, the function has no way to know how many elements the array holds →\rightarrow the length must always travel as a separate parameter.

How Long Is This Array?

Instead of typing an array’s length by hand, you can work it out with sizeof:

int nums[5] = {1, 2, 3, 4, 5};
int length = sizeof(nums) / sizeof(nums[0]);
printf("length = %d\n", length);

Output:

length = 5

  • sizeof(nums) is the whole array in bytes: 5 ints ×\times 4 bytes = 20

  • sizeof(nums[0]) is one element: 4 bytes

  • 20 / 4 = 5 elements. Change the [5] and length follows automatically.

A Word of Warning: sizeof Stops Working

The same line, moved into a function:

void print_length(int arr[]);

int main() {
    int nums[5] = {1, 2, 3, 4, 5};
    print_length(nums);
}

void print_length(int arr[]) {
    int length = sizeof(arr) / sizeof(arr[0]);
    printf("length = %d\n", length);
}

Output: length = 2

  • Inside the function, arr is a pointer, so sizeof(arr) is 8 bytes, not the array. 8 / 4 = 2: the wrong answer

  • gcc warns about this line, so read your warnings. The fix is on the next slide.

The Fix: Pass the Length

A function that prints an array needs the length as its own parameter:

void print_array(int arr[], int size) {
    for (int i = 0; i < size; i++)
        printf("%d ", arr[i]);
    printf("\n");
}

  • int size is a second parameter: the caller tells the function how many elements there are

  • The loop runs up to size, so there’s no sizeof inside the function

  • arr[i] works just as it would in main()

The Fix: Calling print_array()

#include <stdio.h>

// defined after main():
void print_array(int arr[], int size);

int main() {
    int nums[5] = {1, 2, 3, 4, 5};
    int length = sizeof(nums) / sizeof(nums[0]);
    print_array(nums, length);
    return 0;
}

Output: 1 2 3 4 5

  • In main(), nums is still an array, so sizeof gives the right length

  • Work out the length there, and pass it along with the array

  • No & on nums: its name already decays to the address of nums[0]

Changing an Array In Place: The Function

Now add a second function, one that changes the array:

void square_elements(int arr[], int size) {
    for (int i = 0; i < size; i++)
        arr[i] = arr[i] * arr[i];
}

  • The same two parameters as print_array(): the array and its length

  • arr[i] = arr[i] * arr[i]; writes each square back into the array

  • arr holds the address of main()’s array, so each write lands in main()’s array, not in a copy

Changing an Array In Place: Calling It

#include <stdio.h>
void print_array(int arr[], int size);      // both defined
void square_elements(int arr[], int size);  // after main()

int main() {
    int nums[5] = {1, 2, 3, 4, 5};
    int length = sizeof(nums) / sizeof(nums[0]);
    printf("Before: ");
    print_array(nums, length);
    square_elements(nums, length);
    printf("After:  ");
    print_array(nums, length);
    return 0;
}

Output:

Before: 1 2 3 4 5
After:  1 4 9 16 25

  • square_elements(nums, length) changes nums itself, with no &

  • Compare a plain int, which needed int * and * to do the same

Passing Strings to Functions

Passing Strings to Functions

A string is an array of char ending with '\0' (recall the lecture on strings and arrays); since arrays pass by reference, so do strings.

  • When you pass a string to a function, you’re actually passing a pointer to its first character.

  • String parameters are usually written as char *s or char s[]; both are treated as pointers inside the function.

Example prototypes:

void print_message(char *msg);
void print_greeting(char greeting[]);

Read-Only Memory

A string can live in two kinds of memory:

  1. String literal: char *name = "Turing";

    • The letters are stored in read-only memory: the program can read them, but not change them. name just points to them.

    • Changing one, name[0] = 't';, usually crashes the program (segmentation fault).

  2. Character array: char name[] = "Turing";

    • The letters are copied into the array, in memory the program can change.

    • Safe to change: name[0] = 't';

Important Distinction

Both can be passed to a function, but only a character array can be safely changed by it.

Example: Reading a String (Read-Only)

For a function that only reads a string, a string literal is safe to pass:

#include <stdio.h>

void greet(const char *name);

int main() {
    greet("Alan Turing");   // string literal
    return 0;
}

void greet(const char *name) {
    printf("Hello, %s!\n", name);
}

const in const char *name promises this function won’t change the string. If it tried, the program wouldn’t compile, so a read-only literal is safe to pass.

What const Protects Against

Now suppose greet() tries to change the string it promised only to read:

void greet(const char *name) {
    name[0] = 'a';          // try to change it
    printf("Hello, %s!\n", name);
}

gcc refuses to build the program:

error: assignment of read-only location '*name'

  • const makes the compiler check the function body: no writing through name

  • The program is never built, so it can’t crash

  • Without const, the same mistake compiles, then crashes when it runs (coming up with make_upper())

Example: Modifying a String

A function that modifies a string needs a writable array, not a literal:

#include <stdio.h>
#include <ctype.h>
void make_upper(char s[]);

int main() {
    char name[] = "turing";  // modifiable array
    make_upper(name);
    printf("%s\n", name);    // prints TURING
    return 0;
}

void make_upper(char s[]) {
    for (int i = 0; s[i] != '\0'; i++)
        s[i] = toupper(s[i]);  // a -> A; others unchanged
}

Careful: Passing a Literal to make_upper()

Keep the same make_upper(), but pass it a string literal:

int main() {
    make_upper("turing");    // a string literal
    return 0;
}

Output: Segmentation fault (core dumped), and gcc gave no warning, even with -Wall.

  • "turing" is a string literal: its letters are in read-only memory

  • make_upper() gets the address of those letters, not a copy, so s points straight into read-only memory

  • The first write, s[0] = toupper(s[0]);, tries to change read-only memory, and the program crashes

The fix: copy the letters into a char array first, as on the last slide.

  • Reading with const: reading a literal is always safe

  • Changing a const string: gcc won’t build the program, so it never gets the chance to crash

Returning Multiple Values

Returning More Than One Result

Suppose we want to write functions that each produce two results:

  • one that works out the sum and the difference of two numbers

  • one that finds the smallest and the largest value in an array

So far, a function has handed back its result with return:

int sum(int a, int b) {
    return a + b;    // one result, one return
}

But return gives back exactly one value. What would the return type of sum_diff() even be?

???  sum_diff(int a, int b);

Start with the sum and difference, and try the obvious thing.

A Tempting Attempt

Why not just return both?

int sum_diff(int a, int b);

int main() {
    printf("%d\n", sum_diff(8, 3));
    return 0;
}

int sum_diff(int a, int b) {
    return a + b, a - b;
}

Output:

5

  • Only a - b comes back; the sum is silently lost

  • It compiles with no warning; gcc -Wall says left-hand operand of comma expression has no effect

One return, one value: the results must go out through pointers.

Returning Multiple Values: The Function

The function: two numbers in, two results out.

void sum_diff(int a, int b, int *sum, int *diff) {
    *sum  = a + b;
    *diff = a - b;
}

  • int a, int b are ordinary copies of the two numbers

  • int *sum, int *diff are pointers: addresses of where the caller wants the results

  • *sum = ... and *diff = ... write into the caller’s variables

  • The return type is void: nothing comes back through return; both results go out through the pointers

Returning Multiple Values: Calling It

#include <stdio.h>

// defined after main():
void sum_diff(int a, int b, int *sum, int *diff);

int main() {
    int x = 8, y = 3;
    int total, difference;
    sum_diff(x, y, &total, &difference);
    printf("Sum = %d\n", total);
    printf("Difference = %d\n", difference);
    return 0;
}

Output:

Sum = 11
Difference = 5

  • &total and &difference say where the results go

  • total and difference start uninitialized: sum_diff() fills them in

Smallest and Largest: The Plan

The task: given an array and its length, find both the smallest and the largest value.

  • For {7, 2, 9, 4, 1, 8}: smallest 1, largest 9

The process, in words:

  1. Start min and max at the first element, arr[0]

  2. For each of the other elements, arr[i]:

    • if arr[i] < min, it’s the new smallest: min = arr[i]

    • if arr[i] > max, it’s the new largest: max = arr[i]

  3. Once every element has been checked, min and max hold the answers

Smallest and Largest: The Function

The plan as a function, with the two results going out through pointers:

void min_max(int arr[], int size, int *min, int *max) {
    *min = arr[0];
    *max = arr[0];
    for (int i = 1; i < size; i++) {
        if (arr[i] < *min)
            *min = arr[i];
        if (arr[i] > *max)
            *max = arr[i];
    }
}

  • int arr[], int size: the array and its length

  • int *min, int *max: where the two results go

  • Both start at arr[0]; the loop updates them through the pointers

Smallest and Largest: Calling It

#include <stdio.h>

// defined after main():
void min_max(int arr[], int size, int *min, int *max);

int main() {
    int nums[6] = {7, 2, 9, 4, 1, 8};
    int length = sizeof(nums) / sizeof(nums[0]);
    int smallest, largest;
    min_max(nums, length, &smallest, &largest);
    printf("Smallest = %d\n", smallest);
    printf("Largest = %d\n", largest);
    return 0;
}

Output:

Smallest = 1
Largest = 9

  • nums needs no &: it already decays to an address

  • &smallest and &largest say where the two results go

Summary

Summary

  • Pass-by-value: a function gets a copy of each argument, so changing a parameter never changes the caller’s variable

  • Pass-by-reference: pass a variable’s address so the function can change the original →\rightarrow C still copies the argument, but the copy is an address

  • int *n in the definition, &x at the call site, *n in the body to reach x

  • swap() needs two pointers because it changes two of the caller’s variables

  • Arrays and strings pass by reference automatically: no & needed, the name already decays to an address

  • Inside a function, sizeof measures the pointer, not the array →\rightarrow pass the length as its own parameter

  • A function that changes a string needs a char array; a string literal is read-only, so pass it only to functions that take const char *

  • Returning multiple values: a function returns only one value directly, so extra results go out through pointer parameters
